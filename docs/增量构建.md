# 按阶段增量准备

“准备运行文件 / 重新检查并准备”会先检查输入和已有产物，只重做输入依赖变化或产物校验失败的阶段。未变化的阶段显示“已验证并复用完成阶段”。

| 变化 | 通常需要重做 |
| --- | --- |
| 手柄按键实现、宿主服务代码 | Mac 主程序，以及新运行版本安装 |
| 宿主内存等配置 | Mac 主程序，以及新运行版本安装 |
| CPU 重写器 | 原生代码重写；若输出影响运行时着色器采集或解码，则更新相关后续阶段 |
| 着色器转换器、编译器或图形 ABI | 对应着色器阶段；链版本改变时同时重编译宿主 |
| 游戏本体或更新 | 受影响版本的解包；再按实际程序、资源输出判断重写与着色器阶段 |
| DLC 文件 | DLC 准备及安装；未读取这些 DLC 的阶段保留缓存 |
| 其他游戏的适配配置 | 当前游戏的构建阶段保持不变 |
| 产物损坏、缺失、目录结构不符 | 修复对应阶段；无效输入会阻止构建 |

仍会进行游戏源文件及缓存的完整性校验。复用计算结果不等于跳过文件读取；大型游戏的校验仍需要时间。新运行版本使用独立副本并原子切换，失败或取消不覆盖上一次成功版本及存档。没有任何输入变化且已安装版本校验通过时，复用已有运行版本。

IPA 导出也会复用已校验的构建包。只改变导出位置时，重新校验并复制已有 IPA；输入变化或缓存包损坏时才重新构建应用和打包。Mac 与 iOS 的产物及编译平台仍各自隔离。

## 缓存接续

每个游戏的 Mac 与 iOS 使用独立工作目录，避免因切换平台或更新引擎而清空所有阶段。`identity.json` 记录本次整体身份，`stage-inputs.json` 记录阶段输入键，`checkpoints.json` 记录文件大小及 SHA-256；阶段输入记录另存目录布局，以检查空目录和意外添加的文件。

旧缓存仅在游戏源身份一致、适配模式明确，且能验证原不可变引擎快照与读取器依赖时，尝试接续已完成阶段。来源记录缺失、损坏或旧版派生配置无法证明兼容时，相关阶段会重建一次。不要为了提速手动改写校验清单；“清理缓存”会主动删除可复用的工作产物。

## 开发者约定

实现位于 `Worker/incremental.py`、`Worker/build.py`。阶段键涵盖相关源码、配置、工具链与上游阶段的实际产物；产物相同的重新解包不会自动迫使后续编译。源码分组对未知位置采用保守失效，协调器命令逻辑变化也采用保守重建。上游打包脚本按函数及本地依赖计算指纹，单独修改宿主函数不会自动使解包步骤失效。

工作目录中的引擎代码必须匹配已验证的不可变快照。只有着色器链头、工具锁、生成表和已记录的 package 选择允许由构建流程更新。已安装运行版本另有文件校验清单，避免相同缓存键掩盖运行文件损坏。

运行 `python -B -m unittest discover -s tests -p test_incremental.py -v`，用合成源文件和生产协调器检查实际调用阶段。测试覆盖按键、配置、工具链、资源、DLC、旧缓存迁移、损坏修复、失败重试、取消和平台隔离；不代表真实游戏或手柄实机验收。输入映射是否能通过设置动态调整，仍取决于引擎是否实现 `DM_INPUT_CONFIG`；增量准备不会自动补上该接口。
