# 内置引擎、同步与私有适配

nxnative 内置于 `Engine/nxnative`，保留上游许可、必要源码、游戏配置及其通用依赖，排除截图、游戏、密钥、玩家缓存。`manifest.json` 记录完整上游提交与逐文件哈希。`scripts/sync_engine.py` 只读取 Git 已提交文件，更新时重新应用 `scripts/patches/controller_native.h` 的共用手柄规则；Mac 与 iOS 输入接口变化时停止同步。

同步脚本为 MetalFX 的 SDK 27 内容偏移属性添加 Mac/iOS 编译期保护，保留新 SDK 的运行时检查及旧 SDK 对非零原点的警告；同时保护 iOS 27 的 `CMMotionManager.deviceMotionBody` 声明：SDK 26 编译使用原有方向转换，SDK 27 编译保留运行时版本判断及视图坐标系路径。补丁可重复应用，已知接口变化会中止同步并保留旧快照。

每日 CI 先生成候选快照，再复用完整启动器/引擎测试、编译、打包与搬移验证；成功后只提交 Engine 目录，main 已变化则拒绝过期候选，不强推。每天同步仓库；无常规功能更新时每周发布一次，最新 App/DMG 也可自行编译。

安装包内置已编译读取器及 LibHac，准备工具时校验版本和哈希并复制到私有缓存，无需下载引擎、安装 SDK 或恢复 NuGet。构建应用的机器通过 .NET 10 SDK 编译读取器。`Worker/NspMetadata.cs` 提供内容元数据协议；适配与生成源码只写入私有副本。旧外部目录偏好由内置引擎取代，开发测试仍可在无内置快照的环境指定外部源码。

Mac 和 iOS 都通过 GameController 直接读取手柄，Switch Pro A/B/X/Y 与 Xbox A/B/X/Y 对应游戏 A/B/X/Y；PS 叉/圆/方/三角对应 A/B/X/Y。Apple 已按任天堂手柄印刷字母报告按钮，不能再根据产品名称交换 A/B、X/Y。默认共用补丁 `controller_native.h` 与 Swift 输入测试页均采用这些报告标签；Mac 可在输入编辑器按设备显式选择 Switch 物理位置（交换 A/B、X/Y），详情见[手柄布局](Controller-layouts.md)。原生测试也按此 ABI 验证，不再把 Nintendo 的 `buttonA` 假定为实体 B。摇杆、方向键、菜单键、扳机、多人插槽及失焦/断开清理由上游保留。不模拟键盘，不依赖可选的 `DM_INPUT_CONFIG` 映射接口。当前内置快照未实现此自定义映射接口，编辑器配置仅保存；修复原生默认按键并不等于接通运行时自定义映射。旧游戏需重新准备宿主；切换回旧运行版本也会恢复其旧输入行为。实体手柄测试仍待验收。

整体构建身份包含引擎源码、璃游适配及流水线版本，但工作目录按游戏和目标平台保持稳定。`Worker/incremental.py` 为解包、DLC、版本配置、原生重写、运行时采集/解码、着色器及宿主维护各自输入依赖；阶段同时校验文件哈希、文件集合和目录布局。单独修正手柄头文件可复用代码与着色器，只更新宿主。只有验证原不可变引擎快照后才接续旧缓存，否则相关阶段重建一次。已成功运行版本使用独立副本，原子切换并保留回滚。完整依赖和边界见[增量准备说明](增量构建.md)。着色器链仍优先使用共享 chain header，旧版本才从游戏配置读取；损坏时重建私有副本一次后明确失败。

## Switch 2 目录导入

`Worker/dump.py` 读取 `base/exefs`、`base/romfs`、可选 `updates/<十进制版本>/` 和 `dlc/<Title ID>/<编号>/romfs`。从 NPDM 取得程序 ID，从 NSO 头取得模块构建 ID，只使用已有 nxnative 配置及其指定版本。输入已解密，无需密钥或 NSP 读取器；托管副本按路径、空目录和内容校验，并把 DLC 身份绑定进缓存键。更新使用已合并的完整 RomFS，不再次叠加本体。构建继续使用上游的原生重写、着色器和宿主接口，当前仅开放 Mac 运行。回归用合成目录验证导入、安装、启动参数、重试和清理，不宣称完成真实 Switch 2 游戏游玩验收。

## IPA 接口与进度

`Worker/ipa.py` 使用私有副本内的 `dm/ios/tools/build_ipa.sh`；IPA 入口额外验证 `pack_ipa.py`、`ios_metal.py`、`project.yml` 和 `Sources/main.m`，并检查 iPhoneOS SDK、Metal 和外部安装的 XcodeGen。Mac-only 用户不需要安装 XcodeGen。引擎的 iOS 源码与构建工具随内置快照提供，玩家游戏包不随发行。

Mac/iOS 的缓存身份包含独立的 `target`、工具版本及源文件哈希。NVN 使用 `IOSOUT` 编译 iPhoneOS 库并验证反射中的平台记录；Vulkan 使用 `vk_shaders.py --ios`。生成 IPA 前重新生成当前链的 C1 表，再传入 `PATCHED`、`ROMFS`、`MSL_IOS`、`AOC` 等资源路径，不把 Mac metallib 当作 iOS 库。

有 `IpaWatch` 的引擎提供应用编译和归档计数；标有 `est` 的总量仅显示不定进度。`Progress` 子阶段切换会重置旧计数，普通消息和警告保持计数。无需该可选监视接口也可打包，未知阶段仍显示运行状态与耗时。核心 `run` 桥接分析本次进程的有界输出并关联具体日志；`dmsh_build.py` 的成功/总数用于区分完成、部分警告和零成功失败，不修改上游转换规则。

IPA 是未签名的独立导出，校验 ZIP 结构和成员 CRC 后原子替换目标文件。输入身份和阶段产物未变时复用已校验的构建包，更换导出位置不重新编译；包损坏或输入变化则重建。当前游戏启动语言和键鼠映射属于 Mac 启动设置；iOS 控制和运行设置由内置引擎负责。

启动时通过 `DM_LANG` 传入 `nn::settings::LanguageCode` 标准代码（例如简体中文 `zh-Hans`、繁体中文 `zh-Hant`、英语 `en-US`、日语 `ja`），由引擎的 `GetDesiredLanguage` 接口读取。全局默认与每游戏覆盖保存在启动器偏好中，不进入构建缓存身份；未指定时默认 `zh-Hans`。Worker 拒绝非白名单代码，避免将界面语言标识或错误的 `zhHans` 继续交给游戏。此设置不修改固件、资源或存档，也不保证任意外部引擎及游戏均实现所有语言。
